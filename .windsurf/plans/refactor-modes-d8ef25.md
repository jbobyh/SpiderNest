# Рефакторинг режимов игры (Наследование логики)

Этот план описывает объединение логики `play-mode` и `battle-mode`, чтобы избежать дублирования кода, используя `updatePlayMode` как основной цикл обновления.

## 1. Модификация `play-mode.js`
- Изменить сигнатуру `updatePlayMode`, добавив объект `options = { isBattle: false }`.
- Обновить проверку фазы: разрешить выполнение, если `state.phase === 'battle'` и передан флаг `isBattle`.
- Изолировать логику, специфичную только для исследования:
    - Открытие стен (`handleWallToggle`).
    - Взаимодействие с алтарями и сундуками (F key).
    - Призыв босса (Space key).
- Добавить вызов специфичной для боя логики (обновление босса и спавн врагов), если `isBattle: true`.
- Сделать логику камеры гибкой: если `isBattle`, использовать фиксированный зум и центр из `state.battle`, иначе — следование за игроком.

## 2. Модификация `battle-mode.js`
- Импортировать `updatePlayMode`.
- Переписать `updateBattleMode`:
    - Удалить всю дублирующуюся логику (движение, стрельба, пули, ИИ, частицы).
    - Вызывать `updatePlayMode(state, playerProgress, camera, dt, callbacks, { isBattle: true })`.
    - Оставить только проверку условия победы (когда `activeSpiders` и `pendingSpawns` пустые).
- Удалить все приватные вспомогательные функции, которые теперь есть в `play-mode.js` (`_stepDash`, `_startDash`, `_onPlayerHit` и т.д.).

## 3. Перенос вспомогательной логики
- Перенести `_processPendingSpawns` и `_enemyCopy` в `play-mode.js` или оставить их доступными для `updatePlayMode`.
- Убедиться, что `updateBoss` импортируется в `play-mode.js` для использования в режиме боя.

## Ожидаемый результат
- Удаление ~300 строк дублирующегося кода в `battle-mode.js`.
- Гарантированная идентичность физики и управления игроком в обоих режимах.
- Упрощение поддержки: любые изменения в базовой механике (например, новые пули) теперь вносятся в одном месте.
